# 2. Windows directfs: host files served by the Sentry itself

Nodes: "Open Windows files directly", "Linux file metadata on NTFS", "Files stay editable on Windows", "Root filesystem from an OCI bundle" (ADR 0005, 0007). Everything ran on `windows-latest` (workflow `.github/workflows/windows-fs.yml`); nothing was run on the dev machine except one `fsutil` probe.

CI: https://github.com/lhns/gvisor-windows/actions/runs/45882679959 (windows-fs, green), build.yml (Linux and Windows builds) https://github.com/lhns/gvisor-windows/actions/runs/45882679895 (green).

## Design
Two layers.
- `pkg/sentry/fsimpl/gofer/winhost` (no Sentry dependencies): Linux file semantics on an NTFS folder. A file is identified by its volume serial and 128-bit file ID and is always opened by ID (`NtCreateFile` with `FILE_OPEN_BY_FILE_ID`, always `FILE_OPEN_REPARSE_POINT`), children relative to a directory handle. No handle is kept per file: every read, write, stat or metadata change opens the file for the call with `FILE_SHARE_READ|WRITE|DELETE` and closes it. So Windows editors and git can rename or delete files the guest has open, and the guest still reaches the file after a Windows rename (ID, not path).
- `gofer/winfs_windows.go`: the third inode implementation of the gofer dentry, next to lisafs and directfs. `host_inode.go` (untagged) declares the operation set as an interface (`hostInode`, `hostHandle`) and `inode_impl.go` got one `case hostInode:` per type switch; `handle.go` got a `host` field. Mount: `HostFolderOptions` passed as `InternalData` makes `GetFilesystem` serve a folder (no server, no `fs.client`). `runsc/boot/hostfolder_windows.go` maps the OCI rootfs path and bind mounts (`owner=UID:GID`, `emulate-symlinks`, `case-sensitive`, `cache=exclusive` options) to it; on Linux nothing changes. Default cache mode is shared (revalidating) because Windows programs edit the folder.

Operations: open/create, mkdir, mknod (all five types), symlink, link (NTFS hard link), unlink/rmdir (POSIX delete disposition: the name goes at once even with open handles), rename (`FILE_RENAME_FLAG_POSIX_SEMANTICS`, across directories, replaces files, replaces empty directories by removing them first, ENOTEMPTY/EISDIR/ENOTDIR checked, NOREPLACE), readdir (NtQueryDirectoryFile with file IDs, d_type from attributes), readlink, stat/statx, setstat (mode, uid, gid, size, times), xattrs, statfs, read/write/pread/pwrite/fsync/fallocate(mode 0).

## ADS format
Stream `:gvisor.meta` of the file (directories too), little endian: `"GVM1"`, u32 mode (full st_mode), uid, gid, rdev major, rdev minor, u32 target length + target (emulated symlinks), u32 xattr count, then per xattr u16 name length, name, u32 value length, value (sorted by name). A file without the stream has the mount defaults (owner 0:0, 0644/0755, read-only attribute clears the write bits). A stream write restores the file's mtime. Emulated specials (fifo, socket, char, block, emulated symlink) are empty files with the SYSTEM attribute so a listing needs no stream read (DT_UNKNOWN). Symlinks are native NTFS symlinks (created with the unprivileged flag) for plain relative targets, emulated for absolute targets, `:` `\` and similar, or when forced. Names: `: \ < > " | ? *` and control characters are stored as U+F000+c (WSL style) in both directions, so a guest name with `:` cannot reach a stream.

## Case sensitivity
NTFS directories are case-insensitive by default: in a default directory, `FILE` finds `File` and creating `file` next to `File` fails with EEXIST (measured on CI). Per-directory case sensitivity (`FileCaseSensitiveInformation`) works: both `name` and `NAME` coexist, lookups are exact, subdirectories inherit the flag (CI). Without admin: on the dev machine (Windows 11 build 26300, non-elevated shell, folder under the user's temp) `fsutil file setCaseSensitiveInfo <dir> enable` succeeded and `a`/`A` coexisted; the CI runner is elevated so it cannot answer this. The `case-sensitive` mount option sets the flag on directories created through the mount and on the root if it is empty; existing non-empty user folders stay insensitive (the flag only changes on empty directories). Linux-image rootfs trees with names differing only in case therefore need that option and an empty target folder.

## What passes (windows-latest)
winhost, 25 tests: create/read/write/truncate/sync, rename (replace file, replace empty dir, noreplace, errors, directory with content), hard links (shared metadata, nlink), native and emulated symlinks (both modes), chmod/chown round trip across remounts and mtime unchanged by chmod, mknod round trip of fifo/socket/char/block, xattrs including `trusted.overlay.whiteout`/`opaque`/`redirect` and `security.capability` (flags, list, remove, coexisting with chmod), readdir with stable inode numbers across remounts and renames, 20000-entry directory, reserved characters in names, a held file renamed and deleted by `os.Rename`/`os.Remove` while the guest still reads and writes it, guest unlink of an open file (pinned), rename of a directory with a held descendant (works), rename over a held file, case sensitivity, statfs, times, codec.
gofer through the VFS (`TestVFS*`, a test context with MemoryFile, clock, limits, mount namespace; no kernel needed): create/write/read/rename/replace/unlink/rmdir, link and symlinks (incl. absolute and `..` targets), chmod/chown/truncate, mknod, xattrs incl. whiteout, Windows renaming and deleting a file the guest has open, listing of 5000 files with stable inodes.

## Open problems
- Opening an emulated FIFO, socket or block device fails with ENXIO (char devices follow the Sentry's device registry); FIFOs could be served by synthetic pipes.
- No handle cache: every I/O call opens the file (measured only as correct, not for speed).
- Revalidation is stat-and-compare per path component; `ReadDirectoryChangesW` invalidation is not done.
- A file replaced by an editor's safe-save gets a new file ID and loses its metadata stream (mode/owner/xattrs); the guest sees defaults.
- A guest name containing a character of U+F000..U+F0FF is indistinguishable from an escaped one; names that are invalid UTF-8 are not preserved; trailing dots/spaces are not escaped.
- Directory-over-empty-directory rename is remove-then-rename (not atomic); replacing a held file may fall back to delete-then-rename.
- Save/restore of host-folder mounts is not supported. Developer-mode symlinks were tested only elevated; the emulated path covers the unprivileged case. Case-insensitive default directories break guests that rely on case-distinct names.
- Not run: any real container; the boot wiring only compiles (Linux and Windows builds green).

Verdict: a Windows folder is served to the Sentry as a Linux filesystem with no gofer, by file ID through short-lived share-all handles with Linux metadata in an NTFS stream, and the host layer and the gofer glue pass their tests on windows-latest; FIFO opens and change notification are still missing.
