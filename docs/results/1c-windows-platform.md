# Phase 1c: the Windows platform for the Sentry (`winstub`)

Code: `pkg/sentry/platform/winstub/` (platform, address space, context, patcher, tests) with `stubasm/`, `pe/` and `x86asm/` moved out of the prototype. Registered as platform `winstub` in `pkg/sentry/platform/platforms/platforms_windows.go`. Workflow: `.github/workflows/windows-platform.yml`. CI run: https://github.com/lhns/gvisor-windows/actions/runs/45878312330 (`windows-latest`, all six test programs pass). Nothing was run on the dev machine.

## Design as built

- **Address range.** `MinUserAddress` 0x400000, `MaxUserAddress` 0x6FFF_8000_0000. Starting at 0x400000 excludes every fixed low Windows region ([0x10000,0x94000), [0xA0000,0xA2000), [0x200000,0x400000)); the stub's own pages (trap table 0xB0000, trap entries 0xC0000, trampolines 0x100000, veneers 0x110000-0x180000) sit in the free gap below it, reachable by `jmp *abs32` and, for sites below 2 GiB, `jmp rel32`. The top is where the per-thread control pages start. Two holes remain inside the range: KUSER_SHARED_DATA at 0x7FFE0000 and one more page near 0x7FFE6000-0x7FFEC000. The platform interface has no holes, so the first `Switch` in an address space reserves [0x7FFE0000,0x7FFF0000) through `mm.MMap` (sealed, no access, found again by name after fork), the way systrap loads its usertrap table. The prototype's 1 GiB "window for Windows" is gone: Windows has the 16 TiB above 0x7000_0000_0000 for its own allocations.
- **Stub process.** One per `AddressSpace`, ~20 ms to start. It is a debuggee created suspended; the whole `[0x10000, 0x7000_0000_0000)` range minus what Windows maps is reserved as placeholders so Windows never allocates inside it. Slot 0 of the control area is an anchor thread parked for good, so the process outlives any guest thread; the first guest thread therefore starts with `CreateRemoteThread` like every other.
- **Threads and locking.** Per stub, one debugger goroutine, `runtime.LockOSThread`ed and never unlocked (its OS thread dies with it): Windows delivers debug events only to the thread that created the process (or attached). It creates the process, sets it up and then only loops `WaitForDebugEvent`/`ContinueDebugEvent`; a handler never waits for the Sentry. Per platform context, one stub thread (slot) created at the first `Switch` in an address space (moved to a new thread if the context's address space changes, as after execve) and terminated on `Release`. The task goroutine that calls `Switch` waits for its thread itself: spin 20000 loads, then sleep on the request event (the stub signals only when the sleep flag is set). Up to 255 guest threads per address space (`MaxThreads` 256, 16 KB per slot).
- **Memory.** `MapFile` takes the section ranges of the memory file (`pgalloc.MemoryFile.Sections`, one `MapViewOfFile3` per chunk piece) and maps whole ranges as one view each (not per page), honoring `at` exactly (R, RW; never X from the shared sections, which are not created executable). Windows can only unmap whole views, so `Unmap` and overlapping `MapFile` unmap the covering views and remap the remainders; placeholders are tracked exactly (maximal free placeholders, split with `VirtualFreeEx(PRESERVE)`, merged with `COALESCE`). `precommit` is ignored; pages are committed by pgalloc's `Allocate` (a SEC_RESERVE section's commit state is per section, so views in any process see it). `PreFork`/`PostFork` are no-ops: the child gets a new stub and the memory manager maps its pmas by `MapFile`; nothing is shared with the parent's stub.
- **Eager patching and W^X.** A mapping with execute permission and no write is copied out of the memory file (`MapInternal`), scanned, patched in the copy and mapped from a private section (`PAGE_EXECUTE_READ`); the memory-file pages keep the original bytes. Patching: `mov $imm,%eax|%rax; syscall` becomes `jmp *slot` (a table entry per site); every other site becomes a jump (rel32, or `jmp *slot` when out of reach) to a veneer holding the displaced instructions; sites that cannot be patched become `ud2` (debugger path, only for real `ud2` sites recorded per address space; any other `ud2` is SIGILL). A mapping with write and execute starts as the shared memory, read-write; the first instruction fetch scans a 1 MiB window and swaps it for a private read-execute copy, the first write swaps it back. The Sentry's restart (rip - 2) is redirected by a per-address-space table to the table entry or veneer, so restarted syscalls re-enter the trampoline.
- **Switch.** Syscall: the registers of the page become `ac` (rax and orig_rax the number, rcx the return address, r11 and flags 0x246). Fault: the debugger handler stores the full context in the page, redirects the thread into the stub's wait routine and publishes a request (the process is continued at once; the Sentry's `MapFile` happens while the thread waits) and `Switch` returns `ErrContextSignal` with SIGSEGV, SEGV_MAPERR/ACCERR, the address and the access type (also SIGILL, SIGTRAP, SIGFPE, SIGBUS for the matching exceptions). Interrupt: `Interrupt` signals the waiter, which suspends the thread, captures the context if it is in guest code (not inside the stub, ntdll or the repair routine; retries otherwise), parks it like a fault and returns `ErrContextInterrupt`; an interrupt with no `Switch` running makes the next `Switch` return at once (`interrupt.Forwarder`). Resume: all registers, `%fs` base, flags and rip come from `ac` every time; a plain syscall return (rcx = rip, r11 = flags) uses the fast tail, everything else (after a fault, an interrupt, a signal, sigreturn, a restart) restores the exact context with a new stub tail (`full`, flags through `popfq` on the stub stack, resume address through `gs:[0x1480]`).
- **%fs.** `arch_prctl` reaches the Sentry as a syscall; `Switch` writes `ac.Fs_base` into the thread page on every resume, the stub loads it with `wrfsbase` on each return and the debugger repairs lost bases as in the prototype.

## Deviations from the ADRs and the prototype

- Trap table not at 0x60000 (ADR 0011) but at 0xB0000, as the prototype already found; the layout moved (see above) and 8192 patch sites fit instead of 4096.
- Patched text is private per address space; there is no per-file site cache (ADR 0012 sketched a list of sites): scanning happens at every `MapFile` of text.
- Guest range starts at 0x400000 instead of 0x10000 (no ud2 trap for guests mapping below 4 MiB; `mmap_min_addr` is effectively 4 MiB).
- One debugger goroutine per stub (the prototype used one thread for all stubs).
- Views are exact, not mapped RWX and lowered: the shared sections are never executable and private text is created executable.
- The platform imports `pgalloc` (for `SectionRange`); it needs a memory file that implements `Sections`.

## Tests (windows-latest, CI run above)

`TestSyscallsFaultsInterrupt` (syscall number and the six arguments through an imm site and a relocated site; rax result visible to the guest; restart at rip-2; SIGSEGV for an unmapped read with `MAPERR`, address and access type; resume after `MapFile`; interrupt of a spinning thread with the exact rip; a pending interrupt returns at once; resume at another rip; a `ud2` site served through the debugger; one hole reservation), `TestExecuteFault` (execute fault, then ACCERR on a non-executable page), `TestUnmapAndRemap` (partial unmaps, remapping holes, replacing mappings, spanning remaps), `TestNewThreadsAndSpeed` (4 threads x 3000 syscalls), `TestForkedAddressSpace` (PreFork/PostFork, a second stub with the mappings copied, a context moved to a third address space), `TestWriteExecute` (JIT page: scan on first fetch, rewrite and rescan). All pass, with the real `pgalloc.MemoryFile`. Syscall round trip with 4 concurrent contexts on 4 vCPUs: 17 us.

## Limits and open points

- FP/SSE state is not saved or restored by the platform (a thread keeps its own; signal frames and sigreturn do not touch it).
- `PrepareForPtrace` and `UserModifiedGS` fail (patched sites cannot be undone; the trampoline uses `%gs`).
- A `syscall` instruction split across two mapping ranges is not found (the scan sees whole mapped ranges only).
- `MaxThreads` 255 per address space; W^X scans 1 MiB windows (a JIT rewriting hot code rescans each time).
- No stub pool: `NewAddressSpace` costs a process start (fork and execve each pay it).
- The stub image is written to a temp file per platform; `Close` removes it when Windows allows.
- No CPU timing/`PreemptCPU`, no `GlobalMemoryBarrier` (membarrier reports unsupported).

## What the Sentry boot path still needs ("Run a static guest from memory")

- `runsc/boot` creating the platform by name `winstub` with a Windows memory file (`runsc/boot/memfile_windows.go`) and `cpuid.Initialize()` working on Windows (it warns about `/proc/cpuinfo`/auxv); `arch` FP state (xsave sizes) is used by the Sentry on signal delivery.
- A loader path that maps an ELF from a memory VFS (tmpfs) with `MapFile` of text (exec) ranges, and a kernel/task start that creates the task's `Context` and runs `Switch`.
- Hooks for guest debugging: `WINSTUB_DEBUG=1` logs scan results and unpatchable sites.

Verdict: PASS. The Sentry's platform interface runs on stub processes on a hosted Windows runner: syscalls, faults, interrupts, resume and a second address space all work through the real memory file.
