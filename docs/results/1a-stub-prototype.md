# Phase 1a: stub and controller prototype

Code: `tools/windows/stubproto/` (own Go module, no Sentry dependency). Workflow: `.github/workflows/windows-stubproto.yml`. CI run: https://github.com/lhns/gvisor-windows/actions/runs/45869823239 (`windows-latest`, Windows Server 2025 build 26100, AMD EPYC 7763, 4 vCPUs, FSGSBASE present). Nothing was run on the dev machine.

## What was built

| piece | where | notes |
|---|---|---|
| stub image | `pe/pe.go` | A hand-written PE32+ (one `.text` section, no imports, no CRT, GUI subsystem, image base 0x7100_0000_0000, 1 KiB file). Its 22-byte entry is `movabs rcx,page0; movabs rax,threadEntry; jmp rax`. Generated by Go at startup (`stubproto mkstub` writes it too), so the build stays Go-only. |
| stub code | `stubasm/` | Go assembly (`tramp`, `trampWait`, `threadEntry`) copied as bytes into the guest at 0xE0000, plus the per-thread `%fs` repair routine generated by `RepairCode`. This package is the part Phase 1c reuses: layout constants, page layout, code. |
| controller | `*_windows.go` | One locked OS thread runs a single event loop: it polls the per-thread shared pages for syscall requests, completes blocked calls, and calls `WaitForDebugEvent`. No locks. |
| ELF loader | `elfload_windows.go` | Static ET_EXEC and static-PIE (load bias 0x5555_5555_4000), 4 KB views of the memory-file section, Linux initial stack with argv, envp and auxv (AT_PHDR/PHENT/PHNUM/PAGESZ/ENTRY/RANDOM/PLATFORM/EXECFN/UID...). |
| scanner/patcher | `elfload_windows.go` | Uses the decoder from `cmd/vendor/golang.org/x/arch/x86/x86asm` (vendored copy in `internal/x86asm`, BSD) for a linear sweep, so only real `SYSCALL` instructions are touched. |
| syscalls | `sys_windows.go` | write, writev, read(0), exit, exit_group, arch_prctl, brk, mmap (anonymous), munmap, mprotect, uname, getpid/gettid/getppid, uid calls, set_tid_address, rt_sigprocmask, rt_sigaction, sigaltstack, clock_gettime, gettimeofday, time, getrandom, fork, vfork, clone (process and thread), wait4, futex (wait/wake with timeouts), nanosleep, clock_nanosleep, sched_getaffinity, getrlimit/prlimit64, fstat/newfstatat for fd 0-2, ioctl (ENOTTY), kill/tgkill (terminate on fatal signals), plus ENOENT/0 stubs. Anything else returns -ENOSYS and is logged once. |

### Design as built

- **Address space.** The controller queries the stub's regions (`VirtualQueryEx`) while it is still suspended and turns every free, 64 KB-aligned gap in [0x10000, 0x7000_0000_0000) into a placeholder (about 112 TiB in 4 gaps). One 1 GiB window at 0x7F0_0000_0000 is left unreserved for Windows. Guest memory is 4 KB views of one pagefile-backed 512 MiB section ("memory file"); lazy anonymous memory (brk, mmap, stack growth) is mapped 8 pages around the fault.
- **Syscall sites.** Patched before any page can execute. `mov $imm32,%eax; syscall` (7 bytes) and `mov $imm32,%rax; syscall` (9 bytes, 2 nops) become `jmp *abs32` through an 8-byte pointer table at 0xB0000; the pointer leads to a 32-byte entry at 0xC0000+32n (`mov $nr,%eax; movabs $ret,%rcx; movabs $tramp,%r11; jmp *%r11`). Every other site becomes `ud2` (the two-byte `syscall` replaced by `0f 0b`).
- **Trampoline.** Saves all guest registers into the thread's shared page, publishes state=1, spins (about 30000 `pause`), then falls back to `NtDelayExecution(500 us)` on a stub-owned stack; on state=2 it reloads all registers, writes the guest `%fs` base with `wrfsbase`, loads the result and jumps to the saved return address. It only uses rax, rcx and r11 (which `syscall` clobbers) before the registers are saved, and never touches the guest stack.
- **ud2 sites.** The debug-event handler never services a syscall. It copies the registers from `GetThreadContext` into the shared page, sets state=1, sets RIP to `trampWait` (the wait half of the trampoline) with `SetThreadContext` and continues. The syscall is then served over shared memory like a patched one, and the return path restores `%fs`.
- **%fs repair.** Access violations at address < 0x10000 or >= 0xFFFF800000000000 while the thread's expected base is non-zero redirect the thread to a per-thread repair routine (S8 method).
- **fork.** A second stub is created, the parent's mapped pages are copied (not COW) into new memory-file pages at the same addresses, the calling thread's register file is copied with rax=0, and the child's first thread is resumed. If the child's Windows regions overlap parent mappings the child is discarded and another is tried.
- **threads.** `clone(CLONE_THREAD)` becomes `CreateRemoteThread(threadEntry, page)` with a new shared page; CLONE_SETTLS, PARENT_SETTID, CHILD_SETTID and CHILD_CLEARTID are handled. A Go runtime works (below).

### Deviations from ADR 0011

1. The trap table is at 0xB0000, not 0x60000: Windows maps fixed regions at 0x10000-0x94000 in every process (below). The `jmp *abs32` scheme still works because 0xB0000 is below 2 GiB.
2. The first guest thread is the stub's own initial thread (the PE entry jumps to `threadEntry`), not a `CreateRemoteThread` thread; later threads use `CreateRemoteThread`.
3. The trampoline finds its page through `gs:[0x28]` (`TEB.ArbitraryUserPointer`, set by `threadEntry`). No stack switch for the fast path: it does not need one because it never pushes; the stub stack is only used for the `NtDelayExecution` fallback.
4. Only two of the four site patterns are patched (`mov $imm32,%eax`, `mov $imm32,%rax`). `xor %eax,%eax; syscall` and register-number sites (including Go's `Syscall6`) go through `ud2`. The 5-byte relocating jump is not implemented.
5. Waiting is a single polling controller thread, not one thread per stub plus events. The stub side has no event handles, only spin plus a timed `NtDelayExecution`.
6. Guest memory is mapped as one 4 KB view per page (see the unmap result below), not per pma. Not implemented: patch cache for file-backed pages, W^X for anonymous executable memory, execve, signals, real files.

## Address-space layout found (50 stub starts, CI)

- Windows mapped exactly these regions inside [0x10000, 0x7000_0000_0000) in all 50 starts: [0x10000, 0x94000) (528 KiB), [0xA0000, 0xA2000), [0x200000, 0x400000) (2 MiB), KUSER_SHARED_DATA at 0x7FFE0000 (4 KiB) and one more 4 KiB page at 0x7FFE6000-0x7FFEC000 whose exact position changed from run to run but was fixed within a run. Nothing else: no varying regions at all. PEB, TEB, initial stack, ntdll and the loader's allocations are above 0x7000_0000_0000, so they never interfere with fork layouts.
- **0x60000 is not free** (inside [0x10000, 0x94000)); **0x400000 and everything above is free** in all 50 starts (the 2 MiB hole ends exactly at 0x400000). Free low space usable for the trap table: 0x94000-0xA0000 and 0xA2000-0x200000.
- Guest-range hole list the platform must report: [0x10000,0x94000), [0xA0000,0xA2000), [0x200000,0x400000), [0x7FFE0000,0x7FFE1000) and the one extra page near 0x7FFE6000-0x7FFEC000 (query it per stub).
- Starting a stub (CreateProcess plus query and 112 TiB of placeholders) is cheap; the whole start to the first served syscall takes 16-18 ms.

They are left untouched; a byte-pattern scanner would have corrupted them. ### Answers to the design questions

- **A debug event stops all threads of the debuggee.** Confirmed: a guest thread counting in a loop advanced by 0 during 20 ms in all 24 held lazy-fault events, and by 390 million during a 100 ms sleep served over shared memory. Hence a ud2 syscall is redirected into the shared-memory path immediately and never serviced inside the event; blocking calls (futex wait, wait4, nanosleep) are completed by the controller later.
- **A 4 KB view cannot be taken out of a larger view.** `UnmapViewOfFile2(view+0x4000, MEM_PRESERVE_PLACEHOLDER)` fails with "Attempt to access invalid address", `VirtualFreeEx(...MEM_PRESERVE_PLACEHOLDER)` on a mapped part fails with "The parameter is incorrect"; `VirtualProtectEx` on one page of a bigger view works, unmapping the whole view works. So the prototype maps one view per 4 KB page (5 us to map, 2.6 us to unmap).
- **Finding the per-thread page without a free register:** `gs:[0x28]` (TEB.ArbitraryUserPointer), written by `threadEntry`; the trampoline's first instruction is `mov r11,gs:[0x28]` (rax, rcx and r11 are dead at a `syscall` site). The `%fs` repair routine instead uses absolute addresses of its own thread's page (generated per thread).
- **`%fs` repair vs a genuine null dereference.** The CPU's current base cannot be read by the debugger. The prototype treats an access violation at < 0x10000 or a non-canonical address as a lost base when the thread's expected base is non-zero, and gives up after 20 repairs at the same RIP within 5 ms. A genuine null dereference therefore costs 20 events before it is reported; a cheaper test needs the trampoline to publish whether it wrote the base last (not done).
- **Not covered:** per-stub debugger thread count, signals, execve, a Sentry-grade memory manager.

## Open problems

- 28% of static sites (38 of 135 in glibc) are ud2 sites, and several are on hot paths; at 60 us each they cost more than the whole fault load of a fork+exec. Extend the patcher (`xor %eax,%eax`, register numbers with a relocating jump) before judging the debugger design on speed.
- The controller busy-polls; with three Go threads on 4 vCPUs the starved guest threads lose `%fs` much more often (20 repairs in one Go hello world). A real Sentry needs events or a bounded spin.
- Page copy for fork is simple copy; a Sentry fork needs COW or lazy copying.
- The first run of the Go guest failed once before the repair guard was relaxed; repeated CI runs were not used to bound flakiness beyond the runs listed.

Verdict: PASS. A suspended PE stub, a Go controller that builds the address space from placeholders and 4 KB section views, eager `syscall` patching with a shared-memory trampoline and debugger-only fault handling run static glibc (non-PIE and PIE), fork+wait, threads and a static Go binary on a hosted Windows runner, at 0.3 us per patched syscall, 60 us per ud2 syscall and about 18 ms per process start.
