# 1b. The sandbox builds for Windows

Node: "Make Linux names resolve on Windows" and "Sentry builds for Windows" (ADR 0006).

## Result
`GOOS=windows CGO_ENABLED=0 go build ./runsc/boot/...` succeeds (249 gvisor packages in the graph); `GOOS=linux CGO_ENABLED=0 go build ./runsc/...` still succeeds. Nothing was run, only compiled.

## Census (type errors of `./runsc/boot` for windows/amd64)
| | errors | packages with errors |
|---|---|---|
| before the shim | 2,222 | 246 |
| after the shim (x/sys copy, 95% of the errors gone) | 109 | 29 |
| after the tag and stub fixes | 0 | 0 |

## The shim
`third_party/golang.org/x/sys` is v0.48.0 as is, plus `unix/*_shim_windows.go`: 36 files generated by `unix/windowsshim_gen` from the linux/amd64 files of the same version (build tag changed to windows, `syscall.Errno`/`Signal` replaced by the shim's own types, the few `syscall` calls that Windows lacks turned into ENOSYS), and `errno_shim_windows.go` by hand. Constants and types are the Linux amd64 values. All 429 exported functions of the shim files end in the raw `Syscall` layer, which returns `ENOSYS`: 143 generated wrappers (`zsyscall_*`) plus the hand-written helpers on top of them. `unix.Errno` is its own type with Linux numbers; `unix.SysProcAttr` is Windows' `syscall.SysProcAttr`.

## What was excluded (build tags)
- Platforms kvm, ptrace, systrap (slimvm is not in the graph): `pkg/sentry/platform/platforms` has a `_windows.go` file that registers nothing.
- hostinet's host netlink (`netlink.go` is `!windows`, `netlink_windows.go` stubs it).
- Linux namespace setup in `runsc/specutils/namespace.go` (`!windows`; `namespace_windows.go` keeps `GetNS`, `HasCapabilities` (false), `KnownNamespaces`).
- Linux assembly `pkg/rawfile/blockingpoll_{amd64,arm64}.s`.

## What was not excluded
nvproxy, tpuproxy, rdmaproxy, cgroupfs, `pkg/seccomp`, lisafs, unet and flipcall are imported directly by `runsc/boot` (not through blank imports) and compile through the shim, so they are in the Windows build and fail with ENOSYS if used. Excluding them needs edits in `runsc/boot`; left for when each is replaced (directfs, ADR 0005). The `pkg/*` Linux-only files that compile through the shim (fdnotifier, eventfd, rawfile, memutil, sighandling, aio, hostfd, fdbased, xdp, stopfd, flipcall futex, syserr host table, abi, tcpip errno) are built for Windows by widening their tag to `linux || windows`; their real Windows versions are later nodes.

## Stubbed
- 429 shim functions return ENOSYS at run time.
- 4 new `_windows.go` files: `rand.Init` (no-op), platforms (empty), hostinet netlink (7 stubs), specutils namespaces (3 functions).

## Edits to shared code
25 hand-edited files plus 13 matching `*_state_autogen.go` tag edits (38 files, all marked `// gvisor-windows:`), `go.mod` (the replace) and `NOTICE`. 5 files were renamed from `*_linux.go` to `*_linuxabi.go` because the suffix would pin them to Linux (git keeps the history).
- Tag widened only: pkg/aio/aio_linux_unsafe.go, pkg/fdchannel/fdchannel_unsafe.go, pkg/fdnotifier/{fdnotifier,poll_unsafe}.go, pkg/memutil/memfd_linux_unsafe.go, pkg/rawfile/{blockingpoll_noyield_unsafe,rawfile_unsafe}.go, pkg/sighandling/sighandling_linux_unsafe.go, pkg/tcpip/link/fdbased/{endpoint,endpoint_unsafe,packet_dispatchers,processors}.go, pkg/tcpip/link/stopfd/stopfd.go, pkg/tcpip/link/xdp/endpoint.go; renamed and widened: pkg/abi/abi_linuxabi.go, pkg/flipcall/futex_linuxabi.go, pkg/sentry/hostfd/hostfd_linuxabi.go, pkg/syserr/host_linuxabi.go, pkg/tcpip/errors_linuxabi.go.
- Tag narrowed: pkg/sentry/socket/hostinet/netlink.go, runsc/specutils/namespace.go, pkg/rawfile/blockingpoll_{amd64,arm64}.s.
- Code: pkg/sentry/fsutil/mmap_precise_file.go (`syscall.Errno` to `unix.Errno`, the same type on Linux), runsc/boot/network.go (`syscall.Dup` to `unix.Dup`).

## CI
Green on ubuntu-latest, both builds: https://github.com/lhns/gvisor-windows/actions/runs/45861578165

## Not verified
Only compilation. `go vet`, tests and any run on Windows are untested; `x/sys/unix` and the `//go:linkname`/assembly uses in the graph (safecopy signal handler, hosttid, cpuid, ...) assemble but are Linux-specific and must be replaced before running.

Verdict: the sandbox side compiles for Windows with 25 hand-edited shared files and one x/sys shim, so the remaining work is real Windows behaviour behind those stubs, not porting the code base.
